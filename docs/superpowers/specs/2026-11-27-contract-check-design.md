# Сверка счёта и письма с договором поставщика

Утверждено пользователем 2026-11-27 («Да, делаем»), после совета Codex.

## Зачем
Схема «оплатите нашему партнёру» проходит мимо всех проверок реквизитов. Письмо приходит с настоящего адреса поставщика (ящик взломан или сотрудник ошибся), счёт выставлен от имени другой, вполне реальной фирмы. Поймать это можно, только если прочитать договор: в нём сказано, что платить нужно напрямую исполнителю. ИИ сравнивает смысл письма и счёта с пунктами договора и показывает две цитаты рядом. Это самый наглядный ответ жюри на вопрос «где ИИ».

## Цели
- У договора в синтетических данных есть пункты об оплате.
- При загрузке PDF или письма сервер находит договор и сравнивает с ним текст счёта и письма. Договор ищется по БИН из счёта, а если не нашёлся — по домену отправителя письма, совпадающему с почтой из договора.
- Ловятся два нарушения: смена реквизитов без допсоглашения (`details_change`) и оплата третьему лицу (`third_party`).
- Новый сигнал `contract_conflict` уровня «проверьте» и блок «Договор» с двумя цитатами рядом: «В письме» или «В счёте» и «В договоре, п. N».
- Новый сценарий на сцене «Оплата партнёру». «Новый для вас поставщик» переезжает в запасные кнопки.

## Не цели
- Загрузка договора пользователем: договоры уже есть у банка в данных клиента.
- Другие условия договора (сроки, суммы, штрафы).
- Подпись подсказок на сервере. Подсказки из документа и сейчас приходят от браузера; подпись — отдельная доработка для всех подсказок сразу.

## Анти-цели
- ИИ не ставит «стоп» и не может смягчить вердикт.
- Не показывать расхождение, если хотя бы одной цитаты нет в тексте дословно (после схлопывания пробелов, без учёта регистра). Цитата договора должна быть внутри текста указанного пункта.
- Если смысл неоднозначен, лучше промолчать, чем выдумать конфликт.
- Сценический режим без сети: только локальные правила.

## Подходы
- А. Встроить сверку в сценарий «Письмо со счётом». Размывает его главную причину (адрес-двойник).
- Б. Отдельный пятый сценарий. Растягивает трёхминутное демо.
- **В (выбран, совет Codex).** Отдельный сценарий «Оплата партнёру» на сцене вместо «Новый для вас поставщик». Адрес настоящий, всё выглядит нормально, подвох виден только в договоре.

## Как устроено
- Сравнение идёт в `/api/extract`, один раз при загрузке. Результат уходит в подсказки (`hints.contract`), `/api/check` и `/api/pay` работают без ИИ, а fingerprint учитывает подсказки. Повторная проверка поэтому детерминирована.
- ИИ (Groq) получает пункты договора и тексты счёта и письма и возвращает `{kind, source, docQuote, clause, contractQuote}`. Пары без дословных цитат отбрасываются. Без сети, без ключа или при ошибке ИИ работают локальные правила по ключевым фразам.
- Контакт для звонка берётся из найденного договора, даже если счёт выставлен от другой фирмы.

## Демо «Оплата партнёру»
- Договор «Дала Транс», раздел 4: «4.1 Оплата производится на расчётный счёт Исполнителя, указанный в разделе 10 настоящего договора.» «4.2 Изменение банковских реквизитов Исполнителя допускается только дополнительным соглашением, подписанным обеими сторонами.» «4.3 Оплата третьим лицам по настоящему договору не допускается.»
- Письмо от `buh@dalatrans.kz` (настоящий домен, проверки почты пройдены, давления нет): «оплату за рейс Алматы — Астана по договору № 14/2025 в этот раз просим направить нашему партнёру ТОО «Арна Карго», счёт во вложении».
- Счёт от ТОО «Арна Карго»: действующая фирма старше 90 дней, счёт в другом банке, Derek видит её впервые.
- Ожидаемый экран: «проверьте», главная причина — «Условия оплаты расходятся с договором», две цитаты (письмо и п. 4.3), действие — позвонить по номеру из договора «Дала Транс».
